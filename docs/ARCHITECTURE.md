# 架构

## 一句话

QQ 是嘴，DSH 是手。中间靠一个文件叫醒。

## 分层

```
┌──────────────────────────────────────────────────────┐
│  你（QQ 客户端，在哪都行）                              │
└───────────────────┬──────────────────────────────────┘
                    │ QQ 协议
┌───────────────────▼──────────────────────────────────┐
│  Linux QQ（跑在 proot 的 Ubuntu 里）                   │
│  └─ NapCat 注入 → OneBot v11                         │
│       HTTP :3000   WS :3001   WebUI :6099            │
└───────────────────┬──────────────────────────────────┘
                    │ WebSocket
┌───────────────────▼──────────────────────────────────┐
│  bridge.mjs（常驻，带着 pid 锁）                        │
│  ├─ 收消息 → 去重 → 落盘 raw.jsonl                     │
│  ├─ 派给 me.mjs（嘴）                                 │
│  ├─ 图片 / 语音（SILK → 文字）                         │
│  └─ 把「这是活」写成 wake.json                         │
└───────────────────┬──────────────────────────────────┘
                    │ 文件 + 定时器
┌───────────────────▼──────────────────────────────────┐
│  DSH proactive 调度器（活在前台服务进程里）              │
│  └─ 看到 wake.json → 叫醒当前会话                      │
│       └─ 会话干活：读屏 / 点击 / 文件 / 命令            │
│            └─ 干完 POST /say → 嘴用自己的话说回去        │
└──────────────────────────────────────────────────────┘
```

## 关键设计

### 为什么用手递话，不用 HTTP

嘴（me.mjs）和手（DSH 会话）是两个进程。最初想用 HTTP 直连，但 DSH 没有给外部留「随便调一个会话」的接口。

能做的是**文件即调度**：DSH 的 proactive 插件有个 `schedule_file` 机制，它读一个 JSON 文件，按里面的条目定时唤醒指定会话。

所以桥写文件，调度器读文件，会话就被叫醒。

### wake.json 的三个硬性要求

```json
{
  "version": 1,
  "entries": [{
    "id": "qq-12345",
    "after_seconds": 2,
    "min_idle_seconds": 8,
    "prompt": "……",
    "target": { "mode": "resume", "session_id": "session-xxx" }
  }]
}
```

1. **必须有顶层 `version: 1`**，否则解析直接失败
2. **entry 必须带 `min_idle_seconds`**，不然会话正忙时重试 3 次就丢弃，话就丢了
3. **`target.mode` 必须是 `resume`** 加当前 `session_id`，否则会开一个新对话——那就不是「同一个我」了

干完活要把文件清成 `{"version":1,"entries":[]}`。

### 去重

NapCat 断线重连后会重放未确认的消息。桥里用 `message_id` 做 Set 去重，不然你会收到两遍同样的回复。

### 半死检测

WebSocket 可能连着但收不到数据。桥里有个 30 秒心跳：如果 90 秒没收到任何数据，主动断开重连。

重连用指数退避（1s → 60s 封顶），避免 NapCat 重启时把日志刷爆。

## 文件在哪

| 路径 | 是什么 |
|---|---|
| `/data/local/tmp/qq/` | proot 栈根目录（Ubuntu rootfs、Linux QQ） |
| `/data/local/tmp/qq/config.sh` | 配置（600 权限） |
| `/sdcard/DeepSeekHarness/qq/` | 运行时数据（日志、会话、待办） |
| `/sdcard/DeepSeekHarness/tools/qq/` | 桥、面板、语音 |
| `/sdcard/DeepSeekHarness/qq/wake.json` | 叫醒文件 |

## 进程

| 进程 | 谁拉起 | 死了会怎样 |
|---|---|---|
| `proot` + `qq` + `Xvfb` | `start.sh`（setsid 脱离） | 看门狗 45 秒内发现并重启 |
| `bridge.mjs` | `start.sh` / 看门狗 | 看门狗拉 |
| `watch.sh` | `start.sh` | 没人拉，只能手动 |
| `panel.mjs` | `start.sh` / 看门狗 | 看门狗拉 |

所有常驻进程都用 `setsid` 脱离 App 进程树，这样关掉 App 不会把它们带走。
